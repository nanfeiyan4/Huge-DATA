本文研究在存储预算约束下为给定查询负载选择索引的问题。方法由四步组成：基于查询谓词与连接列的候选索引生成、基于前缀覆盖关系的冗余消除、以 PostgreSQL 规划器代价（HypoPG what-if）为目标的预算约束贪心选择（含**增量重估**），以及 k-swap 局部精修。我们在 TPC-H（SF1/SF10）上以 22 条查询为负载，在相同资源与相同评估预算下与「无新增索引」基线、去掉冗余消除/去掉增量重估两组消融、随机搜索对照比较，并验证查询结果一致性。

## 1 引言

索引是数据库最重要的物理设计手段，但索引不是免费的：它占用存储、拖慢写入、增加维护开销。工程上真正的问题不是"哪些列可以建索引"，而是**在给定存储预算内，选哪一组索引收益最大**——这是一个带预算约束的组合优化问题，且候选之间存在收益重叠（两个索引可能服务于同一批查询）。

本文的贡献是：
1. 给出一个可复现的、以规划器代价为代理的预算约束索引选择流水线（代码开源在 `idx_lab/`）；
2. 量化"代价代理"与"真实执行加速"的一致性（RQ3），说明该方法在什么条件下可信；
3. 通过消融实验分离出**冗余消除**与**增量重估**各自的贡献（RQ2/RQ4）。

## 2 相关工作

- 索引选择的形式化与贪心/ILP 求解：AutoAdmin（DTA）系列工作把索引选择建模为 what-if 代价最小化；

## 3 方法

### 3.1 负载解析与特征提取
对每条 SQL 抽取：关系（含别名、子查询内关系）、等值谓词列、范围谓词列、连接列、GROUP BY / ORDER BY 列。为覆盖 TPC-H 中"子查询包住筛选条件"的写法，解析器对整个语句做扫描，并用模式(schema)把**非限定列名**唯一映射回表。

### 3.2 候选生成
对每个（查询, 表）：等值列前缀 → 候选；等值列 + 范围列尾 → 候选；连接列单列 → 候选；连接列 + 等值列两种顺序 → 候选；连接列两两组合 → 候选；GROUP/ORDER 列追加 → 候选。列顺序按 `pg_stats.n_distinct` 选择性排序，单索引列数上限 4。

### 3.3 冗余消除
若候选 X 的列序列是候选 Y 的前缀（同表），删除 X：B 树前缀已能服务该访问路径。这是本文的消融点之一。

### 3.4 预算约束下的贪心 + 增量重估
目标：`min Σ_q cost(q, S)`，约束 `Σ size(i) ≤ B`。
- 每轮选择 `Δ收益 / Δ存储` 最大的候选；
- **增量重估**：每次接受一个索引后，重新评估剩余候选在当前集合下的边际收益，从而消除"收益重叠"造成的重复选择；
- 收尾用 k-swap 局部精修（替换一个索引若能降低总代价则接受）；
- 存储量按 `pg_stats.avg_width` 与 `reltuples` 估算（fillfactor 0.9、每元组约 16 B 开销）。

### 3.5 代价代理
用 HypoPG 创建**假设索引**，通过 `EXPLAIN (FORMAT JSON)` 读取规划器总代价；整个过程不建真实索引、不执行查询，单次评估毫秒级。为控制搜索开销，先用"单索引独立收益"预筛（默认 Top-25），再进入贪心。

## 4 实验设置

| 项 | 配置 |
|---|---|
| 机器 | 阿里云 ECS，8 vCPU / 30 GiB / ESSD，Ubuntu 24.04.5 |
| DBMS | PostgreSQL 16.15 |
| 扩展 | hypopg 1.4.0 |
| 关键参数 | `shared_buffers=8GB`、`work_mem=256MB`、`maintenance_work_mem=2GB`、`default_statistics_target=500`、`random_page_cost=4.0`、`jit=off`、`max_parallel_workers_per_gather=0`、`autovacuum=off` |
| 负载 | TPC-H 22 条查询（SF1，lineitem 600 万行，库 1.55 GB） |
| 基线索引 | 仅主键 |
| 测量协议 | 每查询 1 次预热 + 3 次执行取**中位数**；每配置前 `ANALYZE` + `CHECKPOINT`；单查询 `statement_timeout=300s`，超时单独记录；每组测量后比对结果 md5 |
| 预算 | B = 数据量的 20%（202 MB，SF1） |

**测量协议说明**：`jit=off`、关闭并行、关闭 autovacuum 是为降低方差所做的**受控条件**，结论只在该条件下成立（见 §7 效度威胁）。

## 7 讨论与效度威胁

- **单机、单负载**：结论在 8C/30G 单实例与 TPC-H 上成立，规模扩展到 16C/64G 或 JOB 负载时排序可能变化；
- **测量方差**：3 次取中位数，未报告置信区间；对 ±5% 以内的差异不做强结论；
- **代价代理误差**：HypoPG 不统计索引数据分布，规划代价与真实执行并非单调一致，这正是 RQ3 要量化的部分；
- **受控条件**：并行与 JIT 关闭，真实生产环境中并行计划可能改变索引收益排序。
